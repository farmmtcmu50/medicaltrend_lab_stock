# แผนนำ Stock ขึ้นเป็น SaaS

## โครงสร้างที่มีอยู่
ระบบ Stock ใช้ Cloudflare Worker และ D1 โดยลูกค้าแต่ละรายมี Worker/ฐานข้อมูลแยกกัน ส่วนระบบ Subscription ส่วนกลางอยู่ repository `medical-trend-subscriptions` แยกจากโปรแกรม Stock แล้ว การชำระเงินรุ่นแรกใช้รับโอนและผู้ดูแลต่ออายุ ลูกค้าแต่ละรายมีสินค้า หน่วย ราคา Supplier เครื่อง และโลโก้ของตนเองได้

แผนนี้เป็นงานถัดไป ไม่ใช่การยืนยันว่าความสามารถทุกข้อเปิดใช้แล้ว ต้องตรวจสอบโค้ดและการตั้งค่าของระบบส่วนกลางก่อนเริ่มแต่ละระยะ

## ระยะ 1 — พร้อมทดลองใช้กับลูกค้าจริง
- ทำรายการตรวจรับ provisioning: สร้าง D1, migration ครบ, Worker, domain, บัญชี admin และขั้นตอนตั้งรหัสผ่านด้วยตนเอง
- ยืนยัน tenant จากฝั่งเซิร์ฟเวอร์ ห้ามเลือกฐานข้อมูลจากค่า tenant ที่ผู้ใช้ส่งมาเอง ทดสอบว่าลูกค้า A อ่านหรือเขียนข้อมูล B ไม่ได้
- กำหนดสิทธิ์ owner/admin/staff พร้อมทดสอบ API ทุกกลุ่ม รวมถึงต้นทุน การนำเข้า Backup และการตั้งค่า
- ทดสอบเริ่มทดลองใช้ วันหมดอายุ ต่ออายุ ระงับและเปิดกลับ โดยกำหนดพฤติกรรมเมื่อระบบส่วนกลางติดต่อไม่ได้ให้ชัดเจน
- เตรียมข้อตกลงบริการ นโยบายข้อมูล ช่องทางช่วยเหลือ และขั้นตอนส่งออก/ยกเลิกบริการ

เกณฑ์ผ่าน: เปิดลูกค้าทดสอบใหม่ได้ครบโดยไม่แก้ source เฉพาะราย และผ่านการทดสอบแยกข้อมูล สิทธิ์ และอายุสมาชิก

## ระยะ 2 — ดูแลข้อมูลและควบคุมต้นทุน
- สำรองข้อมูลตามรอบ แยกลูกค้า เข้ารหัสและกำหนดอายุเก็บ ทดสอบกู้คืนลงฐานข้อมูลใหม่จริงก่อนเปิดบริการทั่วไป
- บันทึก error, latency, D1 rows read/write และการใช้ storage แยกรายลูกค้า แจ้งเตือนก่อนถึงเพดานบัญชี
- กำหนดแพ็กเกจจากจำนวนผู้ใช้ สินค้า ปริมาณธุรกรรมและพื้นที่เก็บ; ตั้งขีดจำกัดบน API ไม่ใช่เฉพาะหน้าจอ
- รักษา indexed barcode lookup, pagination และหลีกเลี่ยงโหลดคลังทั้งหมดหลังสแกน ทดสอบ workload ที่มีข้อมูลขนาดจริง
- จำกัด login/import/export และ request ขนาดใหญ่; ไม่บันทึก token หรือข้อมูลลับลง log

เกณฑ์ผ่าน: กู้คืนข้อมูลได้ตามเป้าหมายที่ตกลง มีรายงานต้นทุนต่อราย และไม่ให้ลูกค้ารายเดียวใช้ทรัพยากรจนรายอื่นทำงานไม่ได้

## ระยะ 3 — จัดการหลายลูกค้าอย่างปลอดภัย
- ทำ deployment manifest ระบุ Worker, D1 และ schema version ของแต่ละรายในระบบส่วนกลาง
- ออก migration แบบเข้ากันได้กับเวอร์ชันก่อน ทดสอบ tenant นำร่องก่อน rollout เป็นชุด พร้อมสถานะ retry และแผน rollback
- แยกสิทธิ์ผู้ดูแล SaaS ออกจากผู้ดูแลคลังลูกค้า; การเข้าช่วยเหลือต้องมี audit และเหตุผล
- หน้า onboarding ให้ตั้งชื่อ โลโก้ ทะเบียนเครื่อง Supplier และนำเข้าสินค้าผ่าน XLSX ได้
- จัดคู่มือ การฝึกใช้งาน และกระบวนการรับแจ้งปัญหา/เหตุข้อมูลผิดพลาด

เกณฑ์ผ่าน: อัปเดตหลาย tenant ได้ ติดตามรายที่ล้มเหลวได้ และไม่กระทบข้อมูลหรือการตั้งค่าของรายอื่น

## ระยะ 4 — ขยายการขายและชำระเงิน
- เริ่มด้วยบันทึกรับโอน/ต่ออายุและประวัติผู้ดำเนินการตามที่ตกลงไว้
- เพิ่มใบแจ้งหนี้ การแจ้งเตือนครบกำหนด และช่วงผ่อนผัน โดยกำหนดนโยบายส่งออกข้อมูลเมื่อหมดสมาชิก
- เชื่อมชำระเงินอัตโนมัติภายหลัง: ตรวจลายเซ็น webhook, ป้องกันประมวลผลซ้ำ, รองรับยกเลิก/คืนเงิน และกระทบยอด
- ตรวจค่าใช้จ่ายและขีดจำกัด Cloudflare ตามแพ็กเกจที่ใช้งานจริงก่อนตั้งราคาขาย ไม่ใช้ราคาประมาณในเอกสารนี้

## ลำดับแนะนำ
เริ่มระยะ 1 และ 2 กับลูกค้านำร่องจำนวนน้อยก่อนขายทั่วไป จากนั้นทำ rollout หลาย tenant และระบบชำระเงิน กำหนดระยะเวลาและราคาหลังตรวจระบบส่วนกลางกับปริมาณใช้งานจริง
