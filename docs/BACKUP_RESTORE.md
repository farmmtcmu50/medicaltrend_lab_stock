# สำรองและกู้คืนข้อมูล

ใช้บัญชี admin ที่ ตั้งค่า → Database / Export → Backup Database (JSON)
รอข้อความเตรียมไฟล์ครบแล้ว ตรวจไฟล์ `lab_stock_backup_*.json` ใน Downloads และเก็บไว้ในพื้นที่ที่จำกัดสิทธิ์ เพราะมีข้อมูลบัญชีผู้ใช้และต้นทุน

ไฟล์รุ่น 2 ระบุ format, version, วันสำรอง, จำนวนแถว และข้อมูลครบ 17 ตาราง รวมทะเบียนเครื่อง Supplier ประวัติรับเข้า/ใช้/ตัดทิ้ง/ตรวจนับ PR การป้องกันสร้าง PR ซ้ำ การตั้งค่า และบัญชีผู้ใช้ การอ่านตารางอยู่ใน read batch เดียวกันเพื่อให้เป็น snapshot เดียว ไม่รวม secret ของ Worker, Cloudflare bindings, token, ไฟล์ import ที่รอยืนยัน หรือข้อมูลจำกัดการลอง login

Export Excel เป็น `.xlsx` สำหรับเปิดดูข้อมูล ไม่ใช่ไฟล์กู้คืนฐานข้อมูล

## Restore
เลือก JSON Backup และยืนยันจำนวนรายการ ระบบตรวจโครงสร้าง/จำนวนแถว และดาวน์โหลด Backup ปัจจุบันก่อนส่งคำสั่ง Restore หากขั้นดาวน์โหลดไม่สำเร็จจะไม่เริ่ม Restore ควรตรวจและเก็บไฟล์ก่อนกู้คืนให้เรียบร้อย

เซิร์ฟเวอร์ตรวจตารางและคอลัมน์ก่อนลบข้อมูล แล้วแทนที่ข้อมูลใน atomic batch: หาก insert ผิดเงื่อนไขจะย้อนกลับทั้งชุด ไฟล์เก่าที่ครบตารางหลักยังใช้ได้ และสร้างทะเบียนเครื่อง/Supplier จากข้อมูลเดิมเมื่อไม่มีทะเบียนนั้น

Restore แทนที่ข้อมูลเดิมรวมบัญชีผู้ใช้และการตั้งค่า ควรทำในช่วงหยุดรับเข้า/ใช้งานคลัง และทดสอบกู้คืนในพื้นที่แยกก่อนใช้กับฐานจริง

## การตรวจสอบรุ่นนี้
ทดสอบ Backup → Restore กับข้อมูลสต๊อก 21,000 แถว ตรวจจำนวนแถวแต่ละตารางและ foreign key รวมถึงปฏิเสธไฟล์ไม่ครบ/คอลัมน์ผิด/จำนวนไม่ตรงโดยไม่แก้ข้อมูลเดิม ทดสอบหน้าดาวน์โหลดกรณี session หมดอายุ, HTTP error และไม่เริ่ม Restore หากดาวน์โหลด Backup ปัจจุบันล้มเหลว
